## Shared root cause

`requirements.txt` combined `tokenizers==0.23.1` with `transformers>=5.0.0`. Current Transformers releases require `tokenizers>=0.22.0,<=0.23.0`, and no final `tokenizers==0.23.0` package is published. The resolver therefore could not select any valid dependency set.

The Windows job exposed a secondary symptom because PowerShell continued after `pip install -r requirements.txt` failed. Its later partial install did not include ONNX Runtime, so `backend.spec` failed while collecting `onnxruntime` metadata. That was not a separate ONNX defect.

## Corrections

1. Pinned `tokenizers==0.22.2`, which satisfies Transformers and remains compatible with ChromaDB 0.6.3.
2. Added `$ErrorActionPreference = 'Stop'` and `$PSNativeCommandUseErrorActionPreference = $true` to the Windows backend build step.
3. Kept explicit ONNX Runtime/tokenizers packaging collection in `backend.spec` unchanged; once requirements installation succeeds, the specification builds correctly.
4. Updated the gateway-router integration fixture so the mocked limiter exemption returns the original Flask view function. This fixes three blueprint-registration setup errors that only became visible after dependency installation succeeded.
