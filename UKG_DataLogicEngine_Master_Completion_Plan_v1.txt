PHASE 2 / DB-N
	Neo4j + NetworkX  —  Graph-Grounded Reasoning and In-Memory USKD
	Weeks 1–3 (parallel with A)
	

Two sub-tracks run in parallel: (1) wire Neo4j for live graph traversal during L1/L2, and (2) build the NetworkX in-memory graph as the RAM-resident USKD that the canonical architecture specifies. networkx==3.4.2 is already in requirements.txt and two simulation modules import it, but there is still no UskdMemoryGraph, no Neo4j→NetworkX sync, and no NetworkX reasoning substrate wired into the main gateway/TruthCore path.


NetworkX exists only in isolated simulation modules, not as the active USKD substrate
The UKG MVP specification requires an in-memory NetworkX graph as the active reasoning substrate: nodes are loaded from Neo4j at startup into RAM, simulation layers operate on the in-memory graph at zero latency, and new authorized knowledge is written back to Neo4j at L10 Lane B. This is distinct from the live Neo4j queries that power L1/L2 traversal. Both are needed.

9.  Key Principles


* Write the patent disclosure first. The DSQP dynamic persona construction is the core IP. Before writing any DSQP code, produce a dated technical disclosure. Code can always be rewritten; prior art dates cannot be moved backwards.


* DB-N and DB-C start immediately. These sprints run parallel with Phase A and take 2-3 weeks each. By the time Phase C ships, the databases will be populated. Wiring retrieval before populating collections is the most common mistake — it creates working code that returns nothing.


* JRE bundling is a Phase H-1 blocker for desktop Neo4j. On a clean Windows machine without prior Java, Neo4j silently fails. The installer must bundle Eclipse Temurin JRE 17. This is addressed in H-1 but should be considered a prerequisite for any desktop Neo4j testing.


* Phase C before Phase D. The quad_persona/ math layer is 100% written and 0% connected. Connecting it (Phase C) delivers more value per hour than any other task because it activates existing work. DSQP (Phase D) then makes what Phase C connects dynamic.


* NetworkX is the reasoning substrate; Neo4j is the persistent store. Neo4j persists the knowledge graph. NetworkX holds the active working subgraph in RAM for zero-latency simulation during L1-L10 reasoning. Both are needed; they serve different roles.


* LocalSLMProvider already exists and works. sdk/UKG_Python_SDK/ukg_sdk/providers/local_slm.py is a complete Ollama/vLLM adapter. Phase C wires it as a gateway fallback — do not rebuild it.


* SQLite-first, PostgreSQL-compatible. All new code targets SQLite first. No JSONB operators, no CTEs unsupported by SQLite. PostgreSQL compatibility is tested second. Both engines must pass every exit gate.


* Every new Python file must py_compile + survive PyInstaller. Before declaring any phase complete, run python -m PyInstaller backend.spec and confirm the new module loads in the resulting EXE. Add hidden imports and datas entries proactively — finding missing imports at user-install time is avoidable.
