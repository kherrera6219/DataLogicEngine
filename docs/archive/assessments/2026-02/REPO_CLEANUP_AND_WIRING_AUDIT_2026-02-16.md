## Section C: Wiring and dead-code audit

### Wiring issue identified

The following backend blueprints existed but were not registered through the main app route registry path:

1. `backend/contextual_api.py` (`contextual_bp`)
2. `backend/methods_api.py` (`methods_api`)
3. `backend/honeycomb_api.py` (`honeycomb_api`)
4. `backend/routes/search_routes.py` (`search_api`) was not registered by `routes.register_routes(...)` used in `app.py`.

### Wiring fix implemented

Updated `routes/__init__.py` to register:

1. `search_api` under `/api/search`
2. `contextual_bp` under its internal prefix `/api/contextual`
3. `methods_api` under its internal `/api/methods` routes
4. `honeycomb_api` under its internal `/api/honeycomb` routes

Also cleaned duplicated imports and stale comments in route registration areas.

### Runtime verification evidence

Verified route map contains endpoints:

1. `/api/methods/*` (5 routes)
2. `/api/contextual/*` (5 routes)
3. `/api/honeycomb/*` (4 routes)
4. `/api/search/*` (5 routes)

### Dead code status

Post-fix blueprint scan over git-tracked Python files showed no blueprint variables without any `register_blueprint(...)` usage matches.
