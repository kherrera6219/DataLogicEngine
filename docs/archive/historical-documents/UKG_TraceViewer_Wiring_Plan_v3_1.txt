1.3 Authentication Pattern — API Key + Session
From app.py CSRF logic: the backend supports two auth modes. For frontend calls using session cookies, CSRF same-origin checks apply. For API key calls (X-API-Key header or Bearer token), CSRF is bypassed. The frontend uses session-based auth (confirmed in ChatInterface.tsx and settings routes). All trace API calls from the frontend must include the session cookie OR the X-API-Key header — not both.

? NOTE: Frontend fetch calls to /api/v1/trace/* must include credentials: "include" to send the session cookie. No X-API-Key needed for the web UI.

Step A4: Quad Persona Debate (Layer 5)
Layer 5 runs the four expert personas (P8 Knowledge, P9 Sector, P10 Regulatory, P11 Compliance) via the KAMasterController. CHANGELOG v2.5.0 confirms "integration tests for KAMasterController and TruthEngine coordination." Each persona:

3.3 frontend/lib/api/trace.ts — Complete API Client
New file, exact implementation spec
This is the new file that wraps all trace API calls. Every trace component imports from this file — never fetches directly.

// frontend/lib/api/trace.ts

const API_BASE = process.env.NEXT_PUBLIC_API_URL || "http://localhost:5000"
const OPTS: RequestInit = { credentials: "include", headers: {
  "Accept": "application/json", "X-Requested-With": "XMLHttpRequest"
}}

export async function fetchTraceBundle(traceUrl: string): Promise<TraceBundle> {
  const res = await fetch(`${API_BASE}${traceUrl}`, OPTS)
  if (!res.ok) throw new Error(`Trace fetch failed: ${res.status}`)
  const json = await res.json()
  // Backend wraps in standard {success, data, error, timestamp} shape
  return json.data as TraceBundle
}

export async function fetchRunList(page=1, filters?: RunFilters) {
  const params = new URLSearchParams({ page: String(page), ...filters })
  const res = await fetch(`${API_BASE}/api/v1/trace/?${params}`, OPTS)
  if (!res.ok) throw new Error(`Run list fetch failed: ${res.status}`)
  return (await res.json()).data
}

export async function fetchRunDetail(runId: string): Promise<TraceBundle> {
  return fetchTraceBundle(`/api/v1/trace/${runId}`)
}

export async function fetchKADetail(kaId: string) {
  const res = await fetch(`${API_BASE}/api/v1/ka/algorithms/${kaId}`, OPTS)
  if (!res.ok) throw new Error(`KA fetch failed: ${res.status}`)
  return (await res.json()).data
}

4.2 Frontend: useTraceStream.ts — Complete Hook Spec
The hook connects to Socket.IO, joins the run room, and accumulates partial TraceBundle state as layer updates arrive.

// frontend/hooks/useTraceStream.ts
import { useEffect, useState, useCallback } from "react"
import { io, Socket } from "socket.io-client"  // npm install socket.io-client

export function useTraceStream(runId: string | null) {
  const [layers, setLayers] = useState<Partial<FROSTLayer>[]>([])
  const [connected, setConnected] = useState(false)
  const [error, setError] = useState<string | null>(null)

  useEffect(() => {
    if (!runId) return

    // Connect to the same origin; Socket.IO path matches Flask-SocketIO default
    const socket: Socket = io(process.env.NEXT_PUBLIC_API_URL || "", {
      withCredentials: true,       // session cookie
      transports: ["websocket", "polling"],
      path: "/socket.io"
    })

    socket.on("connect", () => {
      setConnected(true)
      socket.emit("join_run_room", { run_id: runId })
    })

    socket.on("trace_stage_update", (data) => {
      setLayers(prev => {
        const updated = [...prev]
        const idx = updated.findIndex(l => l.layer_id === data.layer_id)
        if (idx >= 0) updated[idx] = { ...updated[idx], ...data }
        else updated.push(data)
        return updated
      })
    })

    socket.on("connect_error", (err) => setError(err.message))
    socket.on("disconnect", () => setConnected(false))

    return () => { socket.disconnect() }
  }, [runId])

  return { layers, connected, error }
}

7. Backend Gaps to Close Before Frontend Can Wire
These are the specific backend tasks that must be done before the corresponding frontend component can be tested end-to-end. Ordered by priority.

7.1 Critical — Must Be Done Before Phase 1 Starts

Gap 1: Verify audit_trail in /api/v1/gateway/chat response
The README confirms the [UKG Audit Trace] text footer. But we need the structured audit_trail.complete_trace_url field in the JSON response body. Run this verification:
curl -X POST http://localhost:5000/api/v1/gateway/chat \
  -H "X-API-Key: $UKG_KEY" -H "Content-Type: application/json" \
  -d '{"messages":[{"role":"user","content":"test"}],"model":"gpt-4o","tier":"2"}' \
  | python3 -m json.tool | grep -A5 "audit_trail"
If audit_trail is absent from the JSON body, it must be added to the gateway response serializer in backend/llm_gateway/api.py. This is a 30-minute backend task.

Gap 2: Verify /api/v1/trace/{run_id} returns populated bundle
The endpoint is confirmed registered. The TraceRun DB model has all required columns. But the serializer (to_dict() or schema) may not yet expose nested data like frost_layers, persona_positions, or evidence_sources. Verify:
# After running a Tier 3 query, get the run_id from the response, then:
curl -b session.txt http://localhost:5000/api/v1/trace/{run_id} \
  | python3 -m json.tool | python3 -c "import sys,json; d=json.load(sys.stdin)
  [print(k, type(v)) for k,v in d.get('data',{}).items()]"
If frost_layers or persona_positions are missing/null, the serializer needs to join and include those related models in the response. This is a 1–2 hour backend task.

7.2 Required Before Phase 4 (WebSocket Streaming)

Gap 3: Emit trace_stage_update after each TraceStage write
Confirmed needed per CHANGELOG [Unreleased]. Location: wherever db.session.flush() happens for TraceStage in the simulation layer execution code (likely in simulation/trace_system.py based on CHANGELOG v4.1.5 reference). Add the emit after the flush, as specified in Section 4.1.

Gap 4: Add join_run_room WebSocket handler
The frontend hook calls socket.emit("join_run_room", { run_id }) to subscribe to a specific run's events. This handler needs to be added to backend/websocket/__init__.py or a dedicated trace_events.py registered with the socketio instance.

7.3 Nice-to-Have Before Phase 3 (Evidence Depth)

Gap 5: Ensure evidence_tier and ka_that_invoked fields in TraceEvidence serializer
KA-018 (Source Provenance) is confirmed wired to L2 and L6. The TraceEvidence model should capture the KA ID that invoked the source lookup. If these fields are absent from the TraceEvidence model, add them in a migration. This enables the claim citation map feature.
